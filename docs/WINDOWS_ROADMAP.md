# Windows 优先迭代路线图

> 当前产品范围：只打磨 Windows。移动端、macOS、Linux、TV 等平台在 Windows 达到稳定发布标准后再规划。

## 1. 总原则

1. 每个阶段必须能独立构建、验证、提交和回滚。
2. 每个阶段完成时必须在 `docs/AI_HANDOFF/` 新增真实记录，不能只依赖聊天上下文。
3. 阶段文档必须记录基线、变更文件、设计决策、迁移、验证、遗留问题、下一步、回滚及 Git 推送状态。
4. 不把未运行的测试写成通过；统一标记为 `PASS`、`FAIL` 或 `SKIPPED`。
5. 不提交 Token、密码、Cookie、私人服务器 URL、完整播放 URL、用户数据或本地构建缓存。
6. LinPlayer 采用 AGPL-3.0：只参考用户可观察行为、问题拆分和测试思想，不复制或逐行改写其代码、注释、测试、文案、布局、图标、资源或二进制。

## 2. Windows 主实现

- 当前主交付链：Vue 3/TypeScript + Electron 主进程 + 自研 Qt/QML/libmpv 播放器。
- Tauri/Rust Windows 链保持可构建和兼容，但除非阶段文档明确列入，不要求同一阶段同步重构两个桌面后端。
- 保留现有优势：多线路竞速/健康检测、SMTC、托盘、全局快捷键、通知、稳健图片缓存、自研播放器、双字幕及真实服务器 smoke。

## 3. 阶段计划

### Phase 0：基线与可持续交接

目标：建立独立 Git 分支和既有工作快照，固化 AI 接手入口、阶段模板、Git 规则和 Windows 路线图，并排除本地 AGPL 参考源码。

验收：

- [ ] 已有基线提交和独立分支。
- [ ] AI 接手入口、阶段模板和 Phase 0 文档存在。
- [ ] `npm run build` 和 `npm run check:electron-commands` 通过。
- [ ] 未运行的 Rust 测试明确记录原因。
- [ ] 参考源码未被暂存或提交。
- [ ] 阶段提交已推送到 GitHub，或文档记录认证阻塞。

### Phase 1：安全基础

目标：

- 使用 Electron `safeStorage` 保护 Windows 凭据。
- 将 Emby Token 从普通 `state.json` 幂等迁移到独立加密凭据文件。
- 默认备份剔除 Token、密码和其他秘密。
- 将 Cloud、WebDAV、Alist 秘密逐步移出 renderer `localStorage`。
- 在不破坏 HTTP 私服、图片和播放的前提下收紧 Electron 安全开关。

验收：

- [ ] 旧明文凭据可迁移；失败不会静默丢失登录状态。
- [ ] 新 Token 不再明文出现在 `state.json`。
- [ ] 默认导出配置不包含秘密字段。
- [ ] 删除账号/服务器时同步删除加密凭据。
- [ ] Electron 构建、IPC 覆盖和迁移测试通过。
- [ ] 每项 BrowserWindow 安全调整都有兼容性验证。

### Phase 2：统一网络与播放恢复

目标：统一 HTTP 错误分类、取消、超时和幂等重试；将播放恢复提取为可测试状态机，覆盖临时 URL 过期、重新解析、备用线路、解码回退和次数上限。

验收：

- [ ] 幂等请求按策略重试，非幂等请求不盲目重复。
- [ ] 页面离开、切集和停止可取消在途请求。
- [ ] 播放恢复步骤、次数和最终错误可观测。
- [ ] 快速连续播放/切集不会产生并发会话或进程风暴。
- [ ] 保持现有多线路竞速与健康检测优势。

### Phase 3：媒体源、观看历史与下载

目标：为 Local、WebDAV、Alist 建立统一 Source Backend/Registry；增加本地观看事件与标准媒体身份；下载器增加 Range 探测、分段并行、恢复和原子合并。

验收：

- [ ] 新来源通过注册实现，不复制完整页面和 Store。
- [ ] 本地历史可离线读取并在联网后补偿上报。
- [ ] 分段下载支持重启恢复、校验和合并失败回滚。
- [ ] 旧来源及旧下载配置有兼容迁移。

### Phase 4：Windows 产品完善与发布

目标：接入真实片头/片尾识别并保留固定秒数降级；建立带完整性校验的更新流程；完善发布、升级、回滚、日志脱敏和许可证检查；再按价值选择排行榜、同步、翻译、投屏等功能。

验收：

- [ ] 外部片头服务失败不影响播放。
- [ ] 更新包校验失败时拒绝安装。
- [ ] 干净安装、覆盖升级、配置迁移和回滚均有记录。
- [ ] 产物版本、Git SHA、工具版本和哈希可追溯。
- [ ] Windows 核心播放 smoke 通过后才讨论其他平台。

## 4. Git 规则

- 默认分支前缀为 `codex/`。
- 开始阶段前记录 `git status --short --branch` 与完整 HEAD SHA。
- 不使用 `git reset --hard`、强制推送或无边界清理。
- 不提交 `参考/`、`.lnk`、用户数据、构建缓存或秘密。
- 一个提交只表达一个可验证意图。
- 提交前运行 `git diff --check` 和 `git diff --cached --name-only`。
- 已共享提交使用 `git revert` 回滚，不重写历史。
- 每份阶段文档必须记录提交 SHA 和推送状态。

## 5. 阶段状态

- `planned`：已定义，未开始。
- `in_progress`：正在实现或验证。
- `blocked`：存在明确且可复现的外部阻塞。
- `accepted`：实现、验证、文档和 Git 更新均完成。
- `superseded`：被后继文档替代，并已指向新文档。
