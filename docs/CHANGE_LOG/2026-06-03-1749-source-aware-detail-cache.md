# 2026-06-03 17:49 详情缓存按账号隔离

## 背景

收藏、历史、聚合视界和搜索已经会从多账号/多服务器聚合条目，并在条目上保留 `_source`。但详情缓存仍按纯 `itemId` 存取，在不同服务器存在相同 `itemId` 时，详情页、播放器标题、队列标题和系统媒体控制信息都有读到上一台服务器缓存的风险。

## 本阶段改动

- `library` store 新增 `itemCacheKey` 和 `cachedItem`，详情缓存按 `accountId:itemId` 隔离。
- `loadItem` 写入当前账号对应的缓存 key，避免不同服务器同 ID 互相覆盖。
- 详情页读取路由 query 中的 `account`，进入详情前先切换到对应账号，再加载该账号下的详情。
- 详情页收藏/已看失败回滚重新加载时也写入同一个账号缓存。
- 播放器标题、队列条目和系统媒体控制中心封面/标题读取当前账号下的缓存。

## 验证

- `npm.cmd run build` 通过。
- `git diff --check` 通过；仅提示 Windows 工作区后续可能把 LF 转为 CRLF。
